Module Factory Pipeline

The end-to-end assembly line for a new lesson, exactly as run for Lessons 22–25. Stages 1–3 build, stages 4–6 verify and ship — the author agent never grades its own homework.

Full pipeline protocol
S1

Read the Source Lesson

The orchestrator renders the lesson's PDF pages (printed page + 10) and extracts objectives, worked examples, and every exercise. No printed answer key exists — nothing is transcribed.

Step 1
S2

Scaffold + Author

new-module.mjs creates the folder and draft registry entry; the author agent writes 6 classics whose answers are computed in code, intro scenes with teaching diagrams, and leak-proof practice visuals.

Scaffolder
S3

Wire + Publish

Card visuals (three maps), numbered quest node, intro pack, source extract; flip the registry entry to published and regenerate registry.js — the registry is the single source of truth.

Registry
S4

Independent Verification

Two separate agents: a math re-derivation agent brute-forces every answer from the student-facing text (target: 0 discrepancies), and an adversarial reviewer hunts answer leaks and boundary bugs.

Step 9
S5

Mechanical QA Gates

npm run qa: bank audits, module tests, skill coverage, intro-pack lint, diagram parity, integration. Plus a live browser smoke test of every answer style before shipping.

QA runner
S6

Ship via PR

Feature branch, pull request with verification evidence, then a human-approved merge to main — which is production: GitHub Pages auto-deploys and the live URLs are re-verified.
