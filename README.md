# PMC Math Quest

A static HTML/CSS/JS maths practice app (Year 6 "Think Academy" workbook →
playable missions), built and verified by an agentic pipeline. No build step,
no runtime dependencies.

- **Play (live):** https://anislahlou.github.io/pmc-math-quest/run/pmc_simulation_app.html
- **Command center:** `dashboard/math_skill_command_center.html` — the human map
  of the agent pipeline, mission registry, and release gates.
- **Add a module:** follow `agents/module_factory_pipeline.md` (the canonical
  end-to-end process used for Lessons 22–25).

## Run on any machine (GitHub is the only dependency)

```bash
git lfs install                     # REQUIRED before/next to clone — the source
git clone https://github.com/anislahlou/pmc-math-quest.git   # workbook PDF is in LFS
cd pmc-math-quest
node scripts/static-server.mjs      # http://localhost:8765/  (or just open
                                    # run/pmc_simulation_app.html from disk)
```

Without `git lfs install` the workbook PDF
(`modules/train_problems/source/…pdf`, the source for Lessons 19–28) arrives as
a tiny pointer file — run `git lfs pull` to fix. Everything else is plain text.

| Need | Requirement |
|---|---|
| Play the app | any browser (file://, local server, or GitHub Pages) |
| QA gates | Node ≥ 18 → `npm run qa` (no `npm install` needed) |
| Author a new module | Node + git-lfs + `gh` CLI → see `agents/module_factory_pipeline.md` |
| Optional QA extras | `npm i` + Playwright (integration gate), `ANTHROPIC_API_KEY` (pedagogy gate) — both SKIP cleanly if absent |

## Folder Map

- `run` — the student app (missions hub) + `card_visuals.js` (three per-module visual maps).
- `dashboard` — the agent orchestration command center.
- `agents` — **`module_factory_pipeline.md` (the process)** + per-discipline design protocols.
- `modules` — one folder per mission + `registry.json` (**single source of truth**; `registry.js` is generated by `scripts/sync-registry-js.mjs`).
- `qa` — mechanical release gates (`npm run qa`).
- `scripts` — `new-module.mjs` scaffolder, `static-server.mjs`, registry sync.
- `source` — source page images used by older modules.

## Missions

The mission list lives in `modules/registry.json` (status `published` = live on
the missions page — 13 missions as of Jul 2026, Lessons 22–25 added via PRs
#1–#8). The missions hub and dashboard both render directly from the registry,
so the registry is always the accurate list.

## Quality Check

```bash
npm run qa            # registry sync lint + all gates
```

Known baseline: 3 pre-existing skill-coverage failures (`u2t2_units`,
`pascal`, `triangle_sides`) predate the pipeline and are documented in
`agents/module_factory_pipeline.md`. Any other failure blocks release.

## Releases

`main` **is** production: GitHub Pages serves the repo root from `main`.
All changes land via feature branch → PR → owner-approved merge → automatic
Pages deploy (verify the live URLs after the build).
